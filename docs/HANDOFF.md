# 인수인계 — 다른 머신에서 이어서 작업할 때 먼저 읽는 문서

이 파일이 **세션을 넘어 살아남는 유일한 상태 기록**이다. 컨테이너의 스크래치패드
(`/tmp/claude-*/scratchpad`)는 롤백/머신 교체로 사라진다. **원격 저장소만 남는다.**

마지막 갱신: **UX 라운드** — 채집 흔적(회색 마름모) 제거 · 채집 재생 300→100초 ·
화면 흔들림 2채널 분리. 그 앞은 2라운드 전부 배포됨(2-a 공중 축 · 2-b 재충전 방패·정화 ·
삼각형 계기 수리 · 2-c 타워 3종).

⚠ **배치 비용 동결은 이 브랜치에 일부러 안 실었다** — `claude/gate2-wip` 에 있고 난이도
봉투 8개를 깬다. 아래 「배치 비용 동결 — 왜 보류됐나」 참조.

핵심 자료구조: `gateOwed`(잔액). 스폰이 `gateOwed = baseDamage` 로 굳히고 문 앞의 한 입이

  Σ(한 입) + (뚫을 때의 잔액) = baseDamage
가 **자료구조로** 성립한다 — 한 마리가 마을에 넣는 총 피해가 근사가 아니라 정의상 보존된다.

### UX 라운드 — 채집 흔적(회색 마름모) 제거

사용자가 두 번 지적했다. 두 번째는 스크린샷으로: *"여기 있는 회색 마름모? 채집후
표시되는 이것을 없애라는 거야."*

정체: `src/render/views/healthbars.ts` 의 **자원 배지 마름모 칩**이다. 자원 칸 하나가
세 상태를 한 모양으로 나른다 — 금색(안 텄음, 부족원 고를 때만) · 한랭색(캐러 가는 중,
항상) · **회색(텄음, 항상)**. 마지막 것이 안 사라져서 판이 진행될수록 회색 마름모가
40~51개까지 깔려 지형을 덮었다.

수정은 한 줄이다: `if (c.taken) continue;` — 텄음 칸은 아예 안 그린다. 정보로도 잃는
것이 없다: **없는 것이 곧 '텄다'** 이고, 부족을 고르는 중이면 금색 칩이 뜬 칸만 갈 수
있는 곳이라 오히려 읽기 쉽다. 셰이더의 `taken` 회색 분기는 도달하지 않는 채로 남겨
뒀다(되살리려면 그 `continue` 한 줄만 빼면 된다).

⚠ **전수 조사로 확정했다** — 이 저장소는 "고치려는 것과 다른 것을 고쳤다"로 세 번 데였다.
`abs(q.x) + abs(q.y)`(마름모를 그리는 식)가 `src` 전체에서 **healthbars.ts 단 한 곳**이다.
바닥의 다른 회색 후보들은 전부 아니다: `props.ts` 의 자갈/흙두덕(3층 지피라 채집으로 안
사라지지만 랜덤 yaw · 3~5px · 어두운 회갈색) · `decals.ts` 배치 슬롯 원판(원형이고 타워
카드를 고른 동안만) · 파괴 잔해(원형) · `grounddetail`(직각 판이 **금지**돼 있고 계약이
잠근다). 사용자가 가리킨 것은 크기·방향이 일정한 빌보드라 배지가 맞다.

⚠ **계약을 걸었다** (`tests/render/healthbars.test.ts`, it 3개). 그리고 판별력을 실측으로
증명했다 — `if (c.taken) continue;` 를 지우면 실제로 빨개진다:
```
  텄음 + 고르는 중: expected 1 to be +0
  적1 + 타워1 + 배지1: expected 4 to be 3
  텄음 + 예약 — taken 검사가 claimed 검사보다 먼저다: expected 1 to be +0
```
사례를 그렇게 고른 이유가 중요하다: 가드를 지우면 taken 칸이 다음 줄
`if (!claimed && !gather.selecting) continue;` 로 떨어지므로 **"텄음+예약없음+안고르는중"
조합은 어느 쪽이든 안 그려져 판별력이 0** 이다. 그래서 selecting 과 예약으로 두 우회로를
각각 막았고, 덤으로 두 검사의 **순서**까지 잠갔다 — 다 캔 직후 아직 그 사람이 칸을 물고
있는 한 틱에 회색 칩이 되살아나는 회귀가 정확히 그 자리다.

### ⚠⚠⚠ 배치 비용 동결 — 왜 이 브랜치에 없나 (`claude/gate2-wip` 에 있다)

스테이지는 기본가 상승**(`PLACEMENT_GROWTH` 1.11→1 · `PLACEMENT_STAGE_STEP` 1.05)으로
바꿨고, 고정가 수준은 사용자가 **1.0(옛 첫 기 값 = 창움막 50)** 을 직접 골랐다.

**그 구성이 난이도 봉투 8개를 깬다.** 스테이지1 완주율이 81% → **100%** 가 되기 때문이다.
```
  [1a] notTrivial 완주율 100% (문턱 ≤90%)   ← 방향이 반대인 유일한 다리가 울렸다
  [4]  밀착 배치가 클리어한다 (38.75%, 문턱 ≤2.5%)
  [6]  불도저 팔이 0회 0골드      ┐
  [7]  unit 팔이 0골드            │ **공허 실패** — 갈래가 그 일을 아예 안 한다.
  [10] 아군 0 · 봉쇄 0            │ 타워가 싸지니 지형을 갈 이유도 아군을 뽑을
  [8]  한 명당 봉쇄 3.72 (문턱 35)┘ 이유도 없어져 잴 표본 자체가 사라졌다.
  [13] 부족이 타워 몰빵을 앞선다
  [collapse] 붕괴 팔이 다섯 다리를 다 못 깬다 (계기 판별력 증명 실패)
```
**적 강화로는 못 산다 — 실측으로 확정했다.** `budgetBase 20→30 · budgetGrowth 1.10→1.12 ·
hpGrowth 1.020→1.028` 로 봉투를 다시 돌리니 **9개 실패 → 10개 실패**로 나빠진다:
`[4]` 와 `1a.notTrivial` 은 고쳐지지만 `1a.floor`(꼬리 34) · `[9]`(승 **0/60 대 0/60** —
이번엔 바닥에서 포화) · `[18]`(채집 85% 대 타워 68.75% = 채집이 지배 전략)이 새로 깨진다.
동결이 난이도의 *수준*이 아니라 **모양**을 바꿨기 때문이다 — 타워가 싸지면 돈이 곧
타워라서 경제 갈래가 지배 전략이 되고, 약한 팔은 전부 지게 되어 비교가 죽는다.

**값싼 해법은 적이 아니라 고정가 수준이다.** 80시드 스윕(`gate2-wip` 의 `balance.ts`
`PLACEMENT_BASE_MUL` 주석에 표 전체가 있다):
```
  BASE_MUL   창움막 s1   승          여유
  배포본                65/80 81.3%  20.85%   ← 목표
  1.0 (사용자 선택)  50  80/80  100%  46.50%
  1.45               73  71/80 88.8%  21.65%   ← 난이도 보존
```
곧 `PLACEMENT_BASE_MUL` 을 1.45 로 올리면 **적 데이터를 한 자리도 안 건드리고** 구조
(스테이지 안 고정 · 업그레이드 상승 · 스테이지마다 상승)를 유지한 채 배포본 난이도로
돌아온다. 사용자 결정 대기 중이다.

⚠ `gate2-wip` 에는 `raidmeasure` hexer 의 옛 문턱(1.35/1.5)을 **역으로 잠근** 코드도 있다
(동결이 효과크기를 압축해서 못 넘는다). 동결을 포기하면 그것도 같이 되돌려야 한다 —
이 브랜치는 이미 되돌아가 있다.

### UX 라운드 — 화면 흔들림 2채널 분리 (사용자 지시)

> "적을 공격할 때마다 판 전체가 지진이 나는 효과가 나는데 … 크리티컬 한 경우에만
>  지진 효과를 넣어줘, 그렇지 않을 때는 지금보다 작게 하거나 고정 시켜서. 판 전체를
>  너무 흔들면 게임 중에 어지러워."

⚠ 이 게임에는 **크리티컬 히트가 없다**(`src/sim` 에 crit 개념이 없다). 여기서
"크리티컬"은 **큰 사건**이라는 뜻으로 읽었다.

**상한만으로는 못 고친다**가 이 수정의 요점이다. `SHAKE_BUDGET` 은 한 프레임 총량을
막지만 착탄은 매 프레임 들어오므로 **상한이 곧 정상 상태**가 된다. 그래서 사건을 갈랐다:

| 채널 | 무엇 | 세기 | 예산 |
|---|---|---|---|
| `quake()` | 보스 등장/처치 · 타워 파괴 · 타워 HP 1/3 · 마을 대량 피격 | **종전 그대로** | 0.5 (그대로) |
| `tap()` | 스플래시 착탄 · 지형 정리 | **고정 0.018** (피해·티어·타워 안 봄) | **120ms 스로틀** |
| 없음 | 잡졸 처치 · 단일 착탄 · 체인 경유점 | — | — |

진원은 착탄 한 줄이었다: `clamp(0.055·s^1.45·shakeMul, 0.03, 0.3)` 이 피해와 타워 종류를
둘 다 곱해서 투석기 한 대가 한 발에 예산의 60% 를 썼다.

⚠ **잦은 사건 채널을 "배치당 예산"으로 짰다가 스스로 잡았다 — 그게 조용히 틀렸다.**
카메라 진폭은 배치마다 초기화되지 않고 **쌓인다**(`amp = min(1, amp + s)`, 감쇠 `exp(−6dt)`).
그래서 정상 상태를 정하는 것은 프레임당 주입량이 아니라 **초당 주입량**이고, 배치 예산은
프레임레이트가 오르면 상한 구실을 못 한다. 60fps 계산:
```
  구: 예산 0.5/프레임         → amp 1.000 (포화) · 오프셋 0.3500
  구: 투석기 착탄 0.284 × 4/초 → amp 0.366        · 오프셋 0.1279  ← 실제 체감
  안(예산 0.05/프레임)         → amp 0.525        · 오프셋 0.1839  ← 안 줄었다
  채택(120ms 스로틀 ≤8.3/초)   → amp 0.035        · 오프셋 0.0123
```
곧 실제 체감 기준 **약 1/10**, 종전 최악 기준 약 1/28. 스로틀 간격 안에 들어온 착탄은
**소리와 파티클은 그대로 나가고 셰이크만 생략된다**.

규칙은 `src/game/shakebus.ts` 로 떼어 냈다 — 의존성 0 · 시계 주입 가능이라
`tests/render/shakebus.test.ts` 가 사용자 요구문을 그대로 계약으로 잠근다. **떼어 내자마자
계약이 하나를 더 잡았다**: 큰 사건 예산을 0.34 로 조였더니 판에서 가장 큰 단일 사건인
보스 등장(`quake(0.4)`)이 잘려 나갔다 — 예산은 겹칠 때를 막는 것이지 가장 큰 하나를 깎는
것이 아니라서 0.5(종전 값)로 되돌렸다.
마을 한 입도 손실이 마을 HP 의 15% 미만이면 `tap` 이다(포위전에서 매 프레임 오던 0.1).
`IMPACT_STYLE.shakeMul` 은 읽는 곳이 없어져 **삭제**했다.
